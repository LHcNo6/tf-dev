# 宠物带货 30 秒短视频工作流

Status: ready-for-agent

## Problem Statement

宠物创作者制作带货短视频时，需要分别准备宠物、商品和场景素材，编写分镜提示词，创建并连接节点，再逐步启动生成。重复操作多，也容易出现素材引用顺序或模型能力不匹配的问题。

## Solution

提供独立的短视频工作流。用户输入创意、剧情或商品卖点，并可上传已有素材；工作流使用 Lengyi 方法生成脚本及资产提示词，搭建画布，生成缺失的必要素材，并在模型支持时生成一条不超过 30 秒的视频。

画布始终创建宠物主角、商品和场景三个图片生成节点。商品节点可选启用；未启用时不作为视频参考，也不虚构商品。

## User Stories

1. 作为创作者，我希望输入一句创意即可开始，以减少准备工作。
2. 作为创作者，我希望输入已有剧情或商品卖点，以保留自己的创作意图。
3. 作为创作者，我希望自动获得脚本和分镜提示词，以便快速制作视频。
4. 作为创作者，我希望默认看到宠物主角、商品和场景节点，以便理解素材结构。
5. 作为创作者，我希望上传已有宠物图片，以使用指定的宠物形象。
6. 作为创作者，我希望上传已有商品图片，以展示实际商品。
7. 作为创作者，我希望上传已有场景图片，以控制视频环境。
8. 作为创作者，我希望对缺少的必要素材自动生图，以减少手动操作。
9. 作为创作者，我希望已有图片的节点跳过生图，以避免重复生成。
10. 作为创作者，我希望选择是否启用商品节点，以便同一流程也能制作普通宠物内容。
11. 作为创作者，我希望未启用商品时不虚构商品，以保持内容真实。
12. 作为创作者，我希望视频默认控制在 30 秒以内，以适合短视频场景。
13. 作为创作者，我希望在模型能力允许时指定时长，以控制成片节奏。
14. 作为创作者，我希望脚本和素材在画布中可查看、修改和替换，以便调整结果。
15. 作为创作者，我希望启动前一次了解生成次数及可获得的费用信息，以便决定是否执行。
16. 作为创作者，我希望确认启动后自动推进同一方案，以减少逐步确认。
17. 作为创作者，我希望生成失败时保留已完成的脚本和素材，以便处理失败项后继续。
18. 作为创作者，我希望看到模型能力不足的具体原因，以便选择合适的模型。
19. 作为创作者，我希望最终在视频节点中播放和下载结果，以便检查与使用成片。
20. 作为创作者，我希望重新打开画布后保留内容与连接，以便继续编辑。

## Implementation Decisions

- 新增面向宠物带货的独立 Skill 工作流，复用现有画布工具、文本节点、图片生成节点和视频生成节点。
- 将 Lengyi 所需规则及引用资料纳入 Toonflow 可读取的范围；明确与现有长篇视频工作流的触发边界。
- 固定创建三个图片节点。商品节点未启用时不参与实际视频参考；启用时可上传或生成。
- 将脚本总览保存在文本节点，将完整视频提示词直接写入视频节点，避免文本引用重复追加。
- 使用节点实际端口和参考顺序建立引用；所需素材完成后才启动视频生成。
- 按已配置模型的真实能力选择模式、素材数量和时长；不静默缩短视频、丢弃参考或切换供应商。
- 一次启动覆盖已展示的生成方案；失败或取消后不自动重复付费调用。
- 首版以当前画布保持可用为前提，不承诺关闭页面或切换画布后的后台续跑。

## Testing Decisions

- 主要在真实宿主画布验证外部行为，避免只测试内部实现或以构建成功代替交互验收。
- 覆盖全自动生图、部分上传、全部上传、商品节点未启用，以及保存后重开。
- 覆盖图片和视频失败、取消、引用顺序错误、模型不支持素材数量或目标时长等情况。
- 核对生成次数、费用未知提示和失败后内容保留。
- 现有插件开发指南要求验证节点添加、连线、保存重开、异步任务及真实画布交互；以此作为验收先例。当前尚未发现可直接复用的对应自动化测试文件。

## Out of Scope

多段视频拼接、批量变体、自动剪辑、通用工作流引擎、关闭画布后的后台续跑，以及自动发布或推送。

## Further Notes

实际生成依赖已配置的文本、图片和视频模型及其供应商能力。Lengyi 的默认声音要求为不生成背景音乐、只生成对应音效；模型不支持时需要明确反馈。
