# 图片与视频生成等待维护

## 行为

画布 Agent 调用一次 `node:waitGeneration` 后，画布工具在内部连续等待；底层每次调用仍不超过30秒，沿用120秒画布调用超时。中间的 `running` 不结束 Agent 工具，不触发新的语言模型请求。任何时刻生成成功或失败立即返回，后续仍须按工作流核验素材、取得采用决定。

| 媒体 | 自动检查本次调用记录 | 检查后最多再等 | 从生成启动计算的总上限 |
| --- | --- | --- | --- |
| 视频 | 10分钟 | 5分钟 | 15分钟 |
| 图片 | 5分钟 | 2.5分钟 | 7.5分钟 |

检查发生时读取对应生成编号的当前状态和模型调用记录，摘要最多4000字符；仅向工具进度发送一次提示。缺少调用记录时明确说明无法核实供应商内部进度，继续等到总上限。已明确失败或取消则返回错误；不会调用生成或取消接口。

达到总上限且仍运行时返回 `waitBudgetExceeded: true`、实际已用时间及检查摘要。该标记只结束本次等待，原任务和已有素材保留，不等同于生成失败，也不会自动重试。稍后继续先查询原编号；重复等待不会重新计时。

## 实现与接口

- `packages/tools/canvas/src/index.ts` 在服务端汇总 `node:waitGeneration`；每次短等待仍经过现有画布桥接，未延长所有工具的超时。工具更新经 SDK 的 `onUpdate` 展示，不作为中间工具结果送入模型。每个工具实例最多保留1000份检查摘要，同一生成在该实例内只检查一次。
- `packages/nodeShared/src/useNodeGeneration.ts` 保存本次挂载期间的生成编号和启动时间。图片、视频状态返回 `attemptId`、`startedAt`、`mediaType`、`modelCallId` 和可用的本次 `modelCall`，并继续返回 `status`、`outputs`、`error`。`getGenerationStatus` 接受可选 `attemptId`；`waitGeneration` 接受可选 `attemptId`、`timeoutMs`（1～30000，供内部短等待使用），原来的空参数调用仍有效。编号变化或不匹配会报错，旧输出不作本次成功依据。
- 图片、视频的启动返回 `{status:"generating",attemptId,startedAt}`。调用记录 ID 与生成编号相同；局部重绘也传递同一编号。节点 AI 的可选第三参数仅传递本地调用标识，不进入供应商请求。
- `packages/nodeScaffold/src/nodeAi.ts` 对图片、视频在请求开始时写入 `running` 记录，结束后按同一 ID 更新；每节点仍最多100条。调用记录窗口显示运行中状态，打开窗口期间每秒刷新已用时间；文本、音频的记录时机和等待策略沿用原行为。
- 2026-11-10 起图片、视频另由服务端在提交前持久化独立调用记录，终态由服务端更新；窗口优先展示独立记录。生成状态工具仍读取本次挂载的节点内记录，独立记录的异常边界见[模型调用记录](nodeModelCalls.md)。

只有提供上述生成元信息的新节点使用合并等待；旧插件按原单次等待合约返回。音频生成、视频尾帧和视频合成的等待规则不在此次修改范围。

## 边界与恢复

画布及节点需要保持打开。停止调用或卸载节点会释放等待，关闭页面后不保证继续生成或自动续跑。持久化的调用记录用于历史查看，不是可跨页面恢复的运行任务；旧画布里遗留的 `running` 记录不能证明任务仍存在。

运行中状态查询失败、生成身份变化或画布不可用时结束依赖链并保留现有文件。等待到上限不会取消生成，但用户主动停止生成、删除节点及关闭画布仍沿用原取消行为。原有算力授权、审片采用和尾帧来源校验保持有效。
