# 通用长视频工作流

把创意、故事或剧本制作成多个视频片段和一个合成视频。用户只要求文字或方案时只交付相应内容，不操作画布或生成媒体。用户明确指定其他工作流时按其范围执行；该流程不支持目标时长或要求时说明冲突。

## 模式与开头授权

开始制作时询问交互模式或自动模式；用户已明确选择则不重复问。交互模式按下文原有具体方案确认执行。自动模式先集中确认目标、视频时长/画幅/分辨率/声音及必要图片规格、图片和视频的供应商与模型或有序候选、总生成调用上限（初次及重试均计入）和每个生成对象的失败重试上限（可为0）。说明具体创作和完整提示词将在授权后形成，费用不可查询时说明算力消耗未知；取得用户对上述范围和自动生成的明确同意，缺项集中补齐。跳过、取消或未回答不授权。仅本次任务有效。

自动模式在授权范围内自行确定剧本、提示词及实际节点方案，不逐阶段询问；按候选顺序选择实际可用且满足全部规格和参考能力的模型。生成前核对实际方案与授权、检查所有计划初次调用可在剩余总次数内完成，并记录每个对象及其尝试次数；每次调用前再核对模型、参数、提示词、真实参考、剩余总次数和该对象的重试余量。所有生成尝试（包括明确失败的尝试）均计入总次数；仅本次明确失败且总次数、该对象重试余量及尚未开始对象的初次调用预算均足够时重试。运行中、取消、等待超时、启动结果或状态不明不得重试；超出范围、缺少必要素材、能力不支持或依赖不可核实时暂停并保留成果。用户中途修改导致实际内容或依赖不明、超出授权时暂停，不把修改当作自动授权。允许自动使用本次成功且可读取的输出作为计划内下游输入，但不声称用户已审阅或采用。画布须保持打开，关闭或切换后不保证续跑。

## 1. 全片和分段

先确认已有内容、目标总时长是否严格、风格、画幅和必要资产。保留用户的剧情事实、顺序和明确限制；只询问无法推断且影响结果的缺项。先规划完整剧情，再按自然节拍列出全片分段表：全局段号、剧情范围、预计时长、每段初始和结束状态、所需真实参考、声音及提示词。一个分段可以包含多个镜头，保持跨段人物、场景和道具信息自包含。

宠物带货任务先使用 `skillOperator(action=list)` 查找 `videoPromptAdapter` 的真实 scope，读取其主文件及 `references/petCommercePlanning.md`，形成全片主播、商品事实、逐句口播、逐镜表演及跨段连续性方案；这只是 PART A 或模型适配的创作输入，不调用 30 秒上限的宠物短片技能。普通长视频不强加宠物及带货内容。没有 skillOperator 时从本轮技能目录按实际位置读取；资料确实不可读时说明并暂停依赖的规划。

若是 Seedance 任务，先用 `skillOperator` 列出并读取实际安装的 `workflow` 技能，将本次模式与已授权范围带入；遵循其中的 Seedance 路由锁存及 PART A 的长视频首尾帧例外，使用开头已确认的模型完成分段提示词规划；不要另写导演规则。第二段起的实际尾帧尚未生成，方案中标明来源为上一段本次尾帧，交互模式提交完整提示词模板和该绑定规则供授权，自动模式记录模板及绑定规则并核对开头范围；不编造参考句柄。真实尾帧就绪后将对应首帧引用按约定填入各段既有提示词字段，保持 A9 外壳和已批准内容。该技能或例外不可读取、模型能力冲突时说明并暂停。其他模型遵守实际能力和用户要求。

非 Seedance 任务在选定实际模型、版本和输入模式后，查找并读取 `videoPromptAdapter` 主文件，由其统一选择官方、第三方 `videoPrompting` 或通用规则；使用第三方时按适配器要求读取其真实 scope 与专篇。按已确定的全片和每段方案逐段适配最终提示词，保留剧情、逐字台词、素材身份与原授权；通用回退标明未核实。适配器主文件不可读时暂停依赖的定稿。若模型变化，重新适配受影响段并按本工作流重新核对授权；不改变用户选择的模型或自动增加调用。

中文口播、动物口型或逐镜时间控制的表现质量缺少资料时不视为不支持：保留目标，标明未经验证，并在已授权范围内尝试。只有接口或可靠能力声明明确不支持必要声音、素材或执行条件时才按冲突处理；不静默改为无声或旁白。

30 秒是本工作流的入口，不是模型能力声明。查询实际模型的 `durationResolutionMap`、比例、声音、参考类型、数量和模式，按有效的时长与分辨率组合规划每段。总时长严格且无法由支持的时长组合精确满足时，展示可行组合或可执行的裁剪方案并等待用户选择，不静默缩短剧情或裁剪；非严格目标说明预计与实际时长可能有差异。

## 2. 画布与素材

执行与交付资料属于 **`workflow` 技能**，不属于 `longVideoWorkflow`。先用 `skillOperator(action=list)` 确认实际安装的 `workflow` 及其 scope，然后用 `skillOperator(action=read, name=workflow, scope=<查到的scope>, path=references/stateAndDelivery.md)` 读取。Seedance 任务提示词定稿后，还须以相同 name 和 scope 读取 `path=references/canvasExecution.md`；其他模型不使用该 Seedance 专用执行路由。若读取失败，先核对目标 name、scope 和 path，并以正确参数重试；只有确认目标资料确实不可读取时才说明缺项并暂停受影响阶段。实时工具 schema 优先。先检查当前画布和已有台账；继续任务时复用实际节点、配置和结果，不凭名称推断成功或采用。

通过 `getCanvas` 发现节点类型，`getCanvasNodes` 读取端口、输出和必要数据，`getCanvasEdges` 分页读取连接，`getNodeTools` 发现节点函数，再用 `addNode`、`connectNodes` 和 `nodeTools` 按实际 schema 操作。节点 ID、类型和端口以现场返回为准；长结果按游标或截断指示续读。避免覆盖已有节点，不直接修改画布 JSON。

若提示词使用 `{{ref N}}`，按目标节点实际入边读取来源输出，并按目标 `referenceOrder` 中对应端口的顺序排列：键为 `encodeURIComponent(JSON.stringify([source,sourceHandle]))`，未列入的保持原入边顺序并排在后面。无输出的连接仍占位并阻止生成。无法核实引用或供应商映射时暂停，不猜编号。

在当前画布已有内容之外创建全片及分段表文本节点、每段一个视频生成节点、一个合成视频节点。使用实际返回的节点类型、端口及节点函数；文本内容用文本节点的工具写入，提示词用生成节点的 `node:setPrompt` 写入，不连接文本重复追加提示词。已有素材优先复用；需要新素材时只创建必要的图片生成节点。实际参考就绪后再连接，核对引用类型、顺序与真实文件。没有文件或输出时不能以名称代替素材。

从第二段起，每段都以紧邻上一段本次视频的尾帧作为首帧，顺序生成。先计划各段初始状态和首帧用途；将尾帧图片实际连接到本段后调用 `node:setFirstFrameBinding` 指定其来源、端口和已核实路径。`node:getConfig` 必须读回相同绑定、`endFrameOptional` 模式、相同的 `firstFrame.path` 且没有 `firstFrameError`；提示词明确要求以该首帧画面为起点并执行本段动作。当前显式首帧绑定仅支持所选模型声明 `endFrameOptional`、且没有其他图片、视频或音频参考的情况；不支持或其他必要参考冲突时暂停，请用户选择模型或调整素材，不丢弃参考。不得把 `startFrameOptional` 单图或普通图片参考当成已验证的首帧。

## 3. 方案与授权

通过 `getNodeTools` 查看 `node:getConfig` schema；选模型或查替代方案时，支持 `includeModels` 的节点用 `{includeModels:true}` 查询完整目录，旧插件按实际 schema 查询。日常复核用空参数读取 `config`、`selectedModel` 和 `matchingModes`；旧插件按返回目录核实。所选模型不存在时暂停，不猜测能力。

逐节点通过 `node:getConfig` 查询并设置支持的供应商、模型、时长、分辨率、画幅、模式和声音；连接实际参考后重新核对匹配模式。模型或引用能力不足时说明具体缺项并保留成果，不静默切换模型或丢弃素材。

交互模式在任何媒体生成之前，展示全部待生成资产及每段的完整提示词、模型、参数、参考来源和用途、次数及可查询费用；无法查询费用时注明未知。对于等待生成的资产，标明参考为指定节点的本次成功输出。获得用户对具体方案的明确授权后，重读节点、配置、提示词、连接和调用前输出；发生影响授权的变化时展示差异，对受影响调用重新确认。没有授权不生成。自动模式按开头范围授权执行，在调用前记录完整方案并核对范围，不要求另行批准具体提示词。

## 4. 生成与核验

使用节点实际提供的 `node:generateImage`、`node:generateVideo` 和状态工具，按照授权先生成缺失资产，再依次生成视频段。保存启动回执的 `attemptId`、`startedAt`，按实际 schema 调用 `node:waitGeneration({attemptId})`。画布工具内部合并连续等待：图片从启动起第5分钟检查本次模型调用记录一次，再等最多2.5分钟；视频第10分钟检查一次，再等最多5分钟。成功或失败立即返回，期间无需每30秒再次请求模型。收到 `waitBudgetExceeded` 时报告仍在运行、等待已达上限，保留任务且停止依赖链，不自动再次等待、取消或重生成；稍后继续先查询原任务。旧插件缺少生成元信息时按其实际单次等待合约操作并说明限制。

每段 `node:waitGeneration` 返回本次 succeeded 后，还须调用 `node:waitLastFrame`：只有 succeeded、尾帧 `attemptId` 与本次启动回执一致、`videoUrl` 与本次视频输出一致、返回的尾帧节点和图片路径可读取，才可连接并绑定到下一段。尾帧 pending/running 时按每次最多30秒继续等待，累计10分钟仍运行则报告待续；failed/cancelled、缺失、来源不符或实际画面与授权计划冲突时暂停。尾帧失败可由用户决定后用 `node:extractLastFrame` 对当前视频重新提取，不重生视频。若无等待工具，读取状态并请用户稍后继续，不假定后台唤醒。画布需保持打开；取消、状态不明或节点卸载时停止依赖链并保留已有成果。生成明确失败时交互模式停止，自动模式仅按开头授权的上限重试。

记录各次尝试的节点、提示词、参数、参考、调用前输出、授权和终态。只有本次 `succeeded` 且实际输出可读取，才把它作为本次结果；若期间手动替换、结果归属不清或无法核实，停止采用并说明。用户稍后继续时重新发现画布及状态，先核实再决定是否启动，避免重复生成。

## 5. 顺序合成与交付

全部计划片段有效后，将每段实际 VIDEO 输出连到合成节点，分页核对入边。通过 `getNodeTools` 查询合成节点实际工具；用 `node:getComposeState` 读取所有连接及片段，再按分段表调用 `node:setClipOrder({sources:[{source,sourceHandle}, ...]})`。该操作要求每个连接恰好一次且均有输出；若存在上传素材、缺段、重复或无效来源，处理后重新读取，不猜顺序。

如已选的严格时长方案需要裁剪，请用户在合成节点中设置每段开始和结束时间；等待用户完成后重新读取并逐项核对，不自行声称已裁剪。读回顺序、来源、路径和裁剪范围，与分段表及各次成功输出逐项核对。再调用 `node:startCompose({clips:[{source,sourceHandle,path,start,end}, ...]})`，参数使用读回的完整有序片段；以返回的 `attemptId` 调用 `node:waitCompose({attemptId})`。每次等待最多 30 秒，返回 running 可继续；累计 10 分钟仍运行则报告待续。输入变化、失败、取消、结果归属不清或工具不可用时停止并保留片段与旧成片。只有对应尝试的 succeeded、`inputsMatchAttempt` 为 true、尝试快照符合分段表且实际输出可读取，才是本次成片。

交付分段节点、合成节点、实际输出路径和可核实的实际时长；区分生成成功、用户采用和完成审片。未实际检查的画面、声音、接缝或时长明确标记，请用户播放确认。合成现有行为会重新编码并统一画面与音频，可能补黑边；不自动添加转场或背景音乐。报告失败或未完成项及恢复所需步骤，不声称关闭画布后仍会后台续跑。
